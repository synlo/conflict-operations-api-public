# Launch roadmap

**The intended release combines agent-first tools and a responsive browser dashboard.** The local connector stays headless, and no separate desktop GUI is required.

These are launch outcomes, not promised dates or claims that all capabilities are already available.

| Milestone | Customer outcome |
|---|---|
| Connect | A supported local AI client connects to an unrelated addon and returns a useful read-only result. |
| Validate | The qualified distribution performs a supported native Workbench check and explains missing prerequisites or a failed check accurately. |
| Resume | An interrupted client reconnects and recovers the existing operation and result without repeating completed work. |
| Remember | The agent retrieves relevant project knowledge with clear evidence scope and project isolation. |
| See your work | Explicitly link a project and view reported activity, result scope and freshness from a signed-in computer or phone. |
| Understand usage | Distinguish free local activity from authorized hosted usage and see account-permitted AddonRelay credit information. |
| Manage connections | Inspect permitted projects/actions and revoke a connection without sharing an owner login. |
| Install and support | The exact artifact has clear installation, compatibility, permissions, upgrade, removal, and troubleshooting instructions. |
| Release | External users complete the advertised agent and browser journeys using the qualified artifact, website and supported contract. |

The current read-only companion provides a starting point for the connection milestone. Full native execution, Brain integration and browser project monitoring remain planned. See [capabilities](CAPABILITIES.md).

## Launch scope

Use the existing local companion and framework. Keep setup lightweight and support terminal-based diagnostics. Qualify the browser dashboard as part of the advertised full product, while keeping local work free and account-optional. Browser monitoring must respect account/project access, accurate result scope and reconnect behavior. A separately labelled local-only preview can remain useful before the full product is accepted.

Paid hosted work remains a separate future track. A monitoring account does not imply enabled checkout, and a dashboard key cannot replace the local executor needed for Workbench. Details of the private implementation plan are maintained outside this repository.
