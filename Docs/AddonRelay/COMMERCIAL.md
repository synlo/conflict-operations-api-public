# Product and commercial direction

## The offer

**Free local developer tools, with optional prepaid hosted investigations when that service is ready.** The local developer path should be useful without purchasing a model subscription, opening a hosted account, or starting a trial.

People using an AI coding client bring their own client and model arrangement. AddonRelay provides the project tools and, as qualified milestones ship, the controlled Workbench connection and project knowledge. It should remain useful when a developer changes AI providers or works without an agent.

## Present availability

This repository is the public documentation and roadmap home, with a retained historical backend subset. It is not an announcement that the full native framework, public Brain, hosted accounts, or checkout are open.

The existing local diagnostic implementation is documented separately from the proposed native launch. See [Capabilities](CAPABILITIES.md) for exact status and [Start here](START_HERE.md) for package expectations.

## Why someone would use it

The intended value is concrete:

- Less repeated setup when a new agent session begins.
- A supported path from a question to the appropriate project check.
- Results that say what was actually observed and under which inputs.
- Recovery that checks existing work before launching another operation.
- Relevant engineering knowledge that stays attached to the project.
- One workflow that both an agent and an experienced developer can use.

These are design goals to demonstrate, not measured claims of faster compilation, lower model usage, guaranteed fixes, or superiority over every development tool.

## Optional paid work

The planned commercial model is prepaid hosted work with a clear quote and bounded scope. A supported release should reserve the authorized amount, settle actual eligible work, and release unused reservations on failure or cancellation according to its published terms.

The direction does not require a mandatory subscription or timed local trial. Connecting a client, reading an existing result, polling status, reconnecting, or running a local Workbench operation should not silently create a hosted charge.

Specific public prices are not activated by this preview. Pricing must be published with the actual service, applicable terms, and operational acceptance. Prepared accounting code or a demonstration checkout is not enough to advertise a live paid service.

Before paid hosted launch, demonstrate account isolation, authentication, quote integrity, duplicate-request handling, cancellation, recovery, delivery, support, and sustainable capacity. Local tools should remain usable when that optional service is unavailable.

## Public launch stages

1. Make the product and present limitations understandable in one public home.
2. Publish a coherent local distribution with a verified download and tested setup.
3. Qualify the first native project workflow and persistent project knowledge.
4. Run a limited external-developer pilot with real setup and recovery observations.
5. Expand supported public use after the pilot's actionable failures are addressed.
6. Open optional commercial services only after their separate acceptance.

The [roadmap](ROADMAP.md) supplies detailed outcomes and acceptance. No promised calendar date is implied by this sequence.

## Distribution rights

The existing [rights notice](../../NOTICE.md) remains in effect. No open-source license has been selected for the retained code. Publishing documentation and source visibility does not grant unrestricted copying, modification, redistribution, or commercial reuse.

The intended SDK/extension distribution needs a deliberate license and third-party rights review. Game assets, Workshop packages, provider code, engine tools, and customer projects have their own owners and terms. They are not included merely because AddonRelay can inspect or help operate a local project that uses them.

AddonRelay is presented as an independent tool project. It is not an official Bohemia Interactive product, and this public plan does not imply endorsement or permission to redistribute the engine.

## Launch messaging

The current accurate headline is **“Connect your AI agent to local Arma Reforger diagnostics.”** After native acceptance, a broader Workbench connection message can be supported by an authentic demonstration.

That demonstration should show an unrelated project, the actual supported client and engine, a useful native result, an interruption/reconnect, and retrieval of the retained result. Label synthetic examples and edited footage. The best product explanation is a workflow another developer can reproduce.
