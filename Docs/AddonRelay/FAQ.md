# Frequently asked questions

## Is this the full framework download?

No. This is the public documentation and roadmap preview with a historical public COAPI backend subset. The complete application, native adapter, and Brain are not installed by cloning it. See [Start here](START_HERE.md) for the current package boundary.

## Can my agent already control Workbench through these six tools?

The six current companion tools are read-only diagnostics and guidance. Native Workbench operations are planned public capabilities. Connecting MCP alone does not provide a compile, packaging, or publishing tool.

## What is Brain?

Planned persistent engineering memory for the selected project. It connects problems, attempted fixes, results, and applicability. It is not a new mandatory language model, and the existing optional local report history is not the complete Brain. See [Brain](BRAIN.md).

## Do I need to use one specific AI provider?

The design uses a local tool connection and project evidence outside the conversation. A compatible client still needs supported configuration and testing. The client supplies its own AI service; the framework should not depend on one vendor's conversation history.

## Can an experienced developer use it without AI?

Yes, the existing local interface provides diagnostic categories without an agent. A shared native developer interface and CLI are part of the public framework roadmap. No AI subscription is required for the human diagnostic path.

## Is everything local?

The local checks process selected inputs on the machine. Results returned to a cloud-backed AI client can be sent to that provider. Legacy hosted settings and any future optional hosted investigation are separate data paths. See [Privacy](PRIVACY.md).

## Does it learn from my project automatically?

The proposed project memory retains engineering evidence for that project. It does not imply model training, public sharing, or cross-customer reuse. Team sharing and reference contributions are deliberate separate features.

## Can it automatically fix every addon problem?

No such guarantee is made. A useful tool identifies evidence, narrows a failure, runs a supported check, and preserves what was learned. Provider ownership, engine behavior, incomplete evidence, and hardware-specific tests still matter.

## Is it free?

Free local tools are the product direction. Optional prepaid hosted work is planned, with new hosted accounts and checkout currently closed. This preview announces no active paid offer. See [Commercial direction](COMMERCIAL.md).

## Is the source open source?

No open-source license has been selected for the retained source. Public visibility is not a general reuse grant. [NOTICE.md](../../NOTICE.md) controls the current publication boundary.

## Does it require the Conflict Operations game addon?

The public framework target is an unrelated developer's addon. The historical backend grew from that project, but its private deployment assumptions must be removed before general native use. Installing a game addon is not the proposed framework onboarding path.

## Does it support every Enfusion game or all MCP clients?

Those claims have not been established. The first native target is a qualified Windows Arma Reforger setup. Supported client and engine versions need a published compatibility record.

## Will it publish my mod or restart my live server?

The current tools do neither. Public native development comes first. Packaging, publication, and production deployment are later separately qualified scopes with explicit permissions.

## What should I send in a bug report?

The component/version, expected behavior, actual outcome, and a minimal reviewed example. Use the repository's template. Keep credentials, private endpoints, full operational logs, personal data, and unlicensed content out of public issues.
